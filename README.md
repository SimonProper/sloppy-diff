# sloppy-diff

A local diff viewer for reviewing changes, AI-written or not, with guided reviews generated by Claude Code or Codex.

- 🌿 **Uncommitted, Branch and Range**: uncommitted changes include new files git doesn't track yet. A branch is compared against wherever it split off, found from the history, so a branch taken off another feature branch is compared against that branch. Its commits can be stepped through one at a time, or narrowed to a span.
- 🔍 **Lines or Tokens**: tokens highlights only the changed pieces of a line, and recognises lines and files that were only reformatted.
- 🪟 **Unified or split** layout, syntax highlighting by [twinkleplop](https://twinkleplop.pngwn.at).
- 🧭 **Guides**: your selected agent reads the commits and splits the change into sections to review in order, every hunk in exactly one section. Steps can be marked reviewed, which folds them away. Guides are saved per commit range.
- 🪐 **Visual explainers**: the tab beside Guide turns a branch, commit, range or pull request into an animated 3D walkthrough. Add an optional focus, then generate scenes you can step through, replay and orbit. Generation keeps running when you switch tabs; explainers are saved per commit range and can be downloaded as HTML. The player loads Three.js from unpkg, so it needs internet access.
- 📂 **Sidebar**: when the diff needs the room, the sidebar folds into a rail of file badges or guide steps, and opens over the diff or docks beside it. Files you open or close stay that way across reloads.
- 💬 **Ask AI**: the agent panel beside the diff lists every chat about it, and starts a new one about the whole change. To ask about lines, drag over line numbers, select code, or press `a` and pick them with the arrow keys, in any view. `⌘↵` asks and opens the answer in the panel, with what the agent thought and read along the way folded above it, and back goes to the list. `↵` is a new line. A thin marker down the right edge of the lines shows the question is there, `q` opens or closes the panel, and follow-ups carry on the same session. The lens shows every chat beside the lines it's about. Questions are saved per commit range, and for uncommitted changes until the lines they're about change.
- 💥 **Blast radius**: the Blast radius button beside picked lines finds what else the change affects. The language's own compiler, through its language server, lists where the declarations the lines are in are used and who calls their callers, and git lists the files that usually change along with theirs. Your selected agent then reads each use and says which the change affects, which this change didn't update, the ways in that reach it, and the tests that cover it. TypeScript, JavaScript and Svelte work out of the box; C and C++ need [clangd](https://clangd.llvm.org) and the `compile_commands.json` a build writes (CMake: `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`), at the top of the repo or in a folder one down. In a git worktree without a build of its own, the main checkout's stands in. Uses are found at the change's head commit, in a worktree kept next to the guides and moved from commit to commit. It borrows the repo's installed packages, and clangd keeps its index there, so later runs only index what changed.
- 🎨 **Themes**: the theme menu picks system, light or dark, and which theme draws each: Sloppy Light and Dark, Catppuccin Latte and Mocha, Rosé Pine Dawn, Solarized Light, Gruvbox Dark, Kanagawa Dragon, Nord, Tokyo Night, Vesper, High Contrast Light and Dark, Neobrutalism and NeXTSTEP, each with the colours its own source gives it. Customize theme opens `/theme`, which shows a theme over a sample diff to tweak its colours, corners and fonts, or add CSS rules of its own. A copy of any theme becomes one of your own, kept as it looked when copied, and a prompt can be copied for an LLM to fill in a theme by name. Picks, tweaks and your own themes are kept in the browser. The built-in themes are defined in `src/lib/themes/themes.ts`.

Everything runs on your machine: the server shells out to `git` and, for guides, explainers and questions, to `claude` or `codex`.

## 🚀 Running

Needs Node 22.12 or later, pnpm and git 2.41 or later (for finding where branches split off). For guides, explainers and questions, install and sign in to either [Claude Code](https://claude.com/claude-code) or [Codex CLI](https://developers.openai.com/codex/cli/) (0.161 or later).

```sh
pnpm install
pnpm dev
```

Open the printed URL and pick a repository. Choose **Claude Code** or **Codex** from the **AI** picker in the header. The choice is remembered in this browser and applies to new questions, guides and explainers. Existing conversations keep their original agent, and jobs already running keep theirs.

The repo picker scans your home folder for git repositories. Its "Choose folder…" button opens the system folder picker on macOS, and on Linux with zenity or kdialog installed.

`pnpm build` then `pnpm preview` runs a built copy on its own port, so it stays put while `pnpm dev` changes underneath it. Rebuild and restart the preview to pick up changes. There's nothing to deploy. sloppy-diff refuses requests from other websites, since any page you visit can reach localhost.

## ⌨️ Keys

| Key     | Where              | What it does                                 |
| ------- | ------------------ | -------------------------------------------- |
| `[` `]` | a commit           | step to the older or newer commit            |
| `j` `k` | a guide            | step to the next or previous section         |
| `s`     | the folded sidebar | open or close it                             |
| `a`     | a diff             | ask about lines, picked with the arrow keys  |
| `c`     | a pull request     | comment on lines, picked with the arrow keys |
| `q`     | a diff             | open or close the agent panel                |
| `⌘↵`    | the question box   | ask and open the lens, `↵` is a new line     |
| `j` `k` | the lens           | step to the next or previous question        |
| `r`     | the lens           | reply with a follow-up                       |
| `t`     | the lens           | show or hide what the agent thought and read |
| `\`     | the lens           | show or hide the question list               |
| `⌘.`    | the lens           | stop the answer being written                |

## ⚙️ Settings

Set these in the environment, or in a `.env` file:

| Variable                | Default                                | What it does                                                                |
| ----------------------- | -------------------------------------- | --------------------------------------------------------------------------- |
| `REPO`                  | the working directory                  | repository opened when the URL doesn't name one                             |
| `REPO_ROOTS`            | your home folder                       | `:`-separated folders the repo picker scans                                 |
| `REPO_SCAN_DEPTH`       | `6`                                    | how many folders deep the scan goes                                         |
| `GUIDES_DIR`            | `.guides` in here                      | where guides, explainers and questions are saved, one folder per repository |
| `AI_PROVIDER`           | `claude`                               | default provider: `claude` or `codex`; the browser picker overrides it      |
| `CODEX_BIN`             | `codex`                                | the Codex CLI executable                                                    |
| `CODEX_MODEL`           | Codex CLI's default                    | default model for Codex jobs                                                |
| `CODEX_GUIDE_MODEL`     | `CODEX_MODEL`                          | Codex model used to write guides                                            |
| `CODEX_EXPLAINER_MODEL` | `CODEX_GUIDE_MODEL` or `CODEX_MODEL`   | Codex model used to write visual explainers                                 |
| `CODEX_ASK_MODEL`       | `CODEX_MODEL`                          | Codex model used to answer questions                                        |
| `CLAUDE_BIN`            | `claude`                               | the Claude Code executable                                                  |
| `CLANGD_BIN`            | `clangd`                               | the clangd executable, for the blast radius of C and C++                    |
| `GUIDE_MODEL`           | Claude Code's default                  | Claude model used to write guides                                           |
| `EXPLAINER_MODEL`       | `GUIDE_MODEL` or Claude Code's default | Claude model used to write visual explainers                                |
| `ASK_MODEL`             | Claude Code's default                  | Claude model used to answer questions about lines                           |

Codex runs in a read-only sandbox with approvals disabled, from an isolated temporary directory. It uses the CLI's existing sign-in while skipping user configuration and project integrations. Its JSON event stream supplies progress and token usage; Codex replies omit dollar costs because the CLI does not report them. Claude and Codex model settings are separate, so a Claude model name is never sent to Codex.
